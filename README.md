# 文件個資去除工具

在自己的電腦上，用 Google Gemma 模型找出 Word、PDF 裡的個資，再標註或換成假資料。
**全程在本機執行，檔案不會上傳到網路。**

支援 macOS 與 Linux。第一次安裝需要下載約 10GB 的模型，請預留時間與硬碟空間。

## 一行安裝

### 方法 A：交給 AI Agent（Codex、Claude Code 等）

打開你的 AI Agent，貼上這一句：

```text
請幫我安裝並啟動 https://github.com/AndyJuang/1030-AI-Demo ，照 repo 裡的 AGENTS.md 執行安裝指令，裝完告訴我網址。
```

Agent 會自己執行安裝腳本，並在遇到需要你處理的事（例如輸入密碼）時通知你。

### 方法 B：自己貼到終端機

```bash
curl -fsSL https://raw.githubusercontent.com/AndyJuang/1030-AI-Demo/main/install.sh | bash
```

腳本會自動安裝 Python 套件、Ollama 和 Gemma 模型，跑完測試後啟動工具，並打開 `http://127.0.0.1:8790`。
可以重複執行；已經裝好的步驟會略過。專案預設放在 `~/1030-AI-Demo`。

## 怎麼使用

安裝完成後，日後要再啟動：

1. 在 Finder 對 `啟動個資去除.command` 按兩下，或在終端機執行 `./run.sh`。
   - 第一次若出現「無法打開」：對它按右鍵，選「打開」，再按一次「打開」。
   - 第一次執行會自動安裝套件，約 1 分鐘。之後幾秒就開好。
2. 瀏覽器會自動開啟 `http://127.0.0.1:8790`。
3. 上傳 `.docx` 或 `.pdf`，按「開始偵測個資」。
4. 檢查清單：不需要處理的取消勾選，漏掉的可以在右側全文選取文字後「加入清單」。
5. 選處理方式，按「產生去識別化文件」，再下載。
6. 用完按「清除伺服器上的暫存檔」。要結束工具，關掉啟動時開的終端機視窗。

### 三種處理方式

| 方式 | 結果 |
| --- | --- |
| 標註類別 | 王大明 → 【姓名】；A123456789 → 【身分證字號】 |
| 統一標註 | 所有個資都換成【機敏個資】 |
| 假資料 | 換成格式相同的虛構資料。同一個人全文都會換成同一個假名 |

每個項目的「取代為」欄位也可以自己填，優先於上面的方式。

## 它怎麼找個資

兩層偵測，結果合併：

- **規則**：身分證字號、手機、市話、電子郵件、卡號、出生日期。格式固定，不會漏。
- **Gemma 模型**：姓名、地址、地號。需要看上下文，由模型判斷。

清單裡的「來源」欄位會標示每一項是「規則」還是「AI」。

## 一定要知道的限制

- **AI 不保證 100% 找得到。** 輸出前請看過清單，輸出後請人工再看過成品。
- **圖片裡的字看不到。** 例如掃描的身分證影本、印章、圖片裡的表格。
- **掃描版 PDF 不能處理**（沒有可選取的文字）。工具會直接告訴你。請先 OCR，或改用 Word 檔。
- **不支援舊版 `.doc`。** 請在 Word 另存成 `.docx`。
- **PDF 含個資的那一行會改用統一的中文字型**，其他行不變。
- **PDF 行距比字級還小的頁面**，個資附近的相鄰文字可能被一併移除。遇到時成品頁面會顯示警告，請人工核對該頁。

### 工具順便清掉的隱藏內容

輸出前後都會檢查，這些地方只要還找得到原始個資，就會在完成畫面用紅字提醒你。

| 格式 | 處理的位置 |
| --- | --- |
| Word | 內文、表格、文字方塊、頁首頁尾、註腳、尾註、註解、追蹤修訂裡已刪除的文字、欄位、超連結目標、文件屬性（作者、標題、主旨、關鍵字）、公司與主管欄位。修訂者與留言者姓名一律改成「匿名」，首頁縮圖會移除 |
| PDF | 頁面文字（含頁面可視範圍外的）、書籤、註解、連結、表單欄位、XMP 中繼資料。內嵌附件一律移除 |

沒處理的：Word 的圖表、SmartArt、內嵌 Excel；所有圖片裡的文字。
PDF 若被改成「掃描加隱形文字」，工具只會改文字層，底下的圖片仍看得到原字。

## 資料放在哪裡

- 上傳的檔案和結果暫存在本資料夾的 `jobs/`。工具每次啟動會全部清空；執行中，超過 1 小時的會在下一次上傳時刪除。
- **原檔和成品都在 `jobs/`，用完請按「清除伺服器上的暫存檔」。**
- 伺服器只綁定 `127.0.0.1`，同一個網路的其他電腦連不到；也會拒絕其他網站對它送出的請求。

## 換模型、換埠號

- 換模型：先 `ollama pull 模型名稱`，再用 `OLLAMA_MODEL=模型名稱 ./run.sh` 啟動。預設是 `gemma4`。
- 換埠號：改 `run.sh` 第一段的 `PORT=8790`。

## 常見問題

| 狀況 | 處理 |
| --- | --- |
| 畫面上方顯示「找不到 Ollama」 | 開啟 Ollama App，或在終端機執行 `ollama serve` |
| 顯示「尚未下載模型」 | 執行 `ollama pull gemma4`（約 10GB） |
| 偵測很慢 | 長文件要逐段請模型判斷，每段約 2 到 5 秒。進度條會顯示第幾段 |
| 啟動說埠號被占用 | 別的程式占用了 8790，改 `run.sh` 的 `PORT` |

## 檔案說明

| 檔案 | 用途 |
| --- | --- |
| `app.py` | 網頁伺服器與 API |
| `pii.py` | 個資偵測（規則 + Gemma）與取代 |
| `docs_io.py` | Word / PDF 讀取與改寫 |
| `static/index.html` | 網頁介面 |
| `install.sh` | 一鍵安裝腳本（下載、裝套件、裝 Ollama 與模型、測試、啟動） |
| `AGENTS.md` / `CLAUDE.md` | 給 AI Agent 讀的安裝與使用說明 |
| `run.sh` | 啟動腳本（建環境、檢查模型、開網頁） |
| `tests/test_redact.py` | 離線測試（不需要 AI）：檢查沒有誤刪、沒有殘留 |
| `tests/test_hidden.py` | 離線測試：Word、PDF 的隱藏位置與行距過緊的案例 |
| `tests/e2e.py` | 端對端測試（需要先啟動工具） |
| `samples/` | 虛構資料的範例檔 |

執行離線測試（改過程式後請都跑一次）：

```bash
.venv/bin/python -W ignore tests/test_redact.py && .venv/bin/python -W ignore tests/test_hidden.py
```
